## O que muda
1. **Reconhecimento da dívida é o 1º passo do chat** (logo após auth+consent), com botões Sim/Não, determinístico e local (não chama n8n antes da resposta), log persistido.
2. **Todo botão carrega `id` numérico**; booleano é fixo **1=sim, 0=não**.
3. **Pagamento = variante A** (D17 fechado): cliente aceita → n8n chama `payment.create` → plataforma valida oferta+matriz, aplica guard, cria agreement+cobrança ASAAS, **devolve o link ao n8n**, n8n envia no chat via `chat.send`. Variante B **fora do escopo**: `payment_origin != 'platform'` → **501 not_implemented**.
4. Entregável obrigatório: **`docs/N8N_TEAM_INTEGRATION_GUIDE.md`** (14 seções, autossuficiente, PT-BR) + `docs/n8n/examples/*.http` + `docs/n8n/fixtures/*.json`.

## Padrão de botões/IDs (contrato §2)
IDs reservados: **1=Sim, 0=Não** (booleano); 2..N itens de lista (`value`=offer_id/PIX/BOLETO/CREDIT_CARD, na ordem exibida); 98=Voltar; 99=Atendente. Booleano só tem 1/0 (+99 opcional). `prompt_kind`: `debt_acknowledgement`, `offer_choice`, `payment_method_choice`, `payment_confirmation`, `generic_yes_no`. n8n pode criar prompts novos (`prompt.ask`) respeitando os reservados; kind desconhecido é aceito+registrado.
Integridade do clique (§2.3): clique referencia `prompt_id`+`button_id`; servidor valida (prompt da sessão, `active`, button existe) senão **409 `prompt_not_active`**; ao responder vira `answered` (+`answered_button_id`,`answered_at`); prompts `active` anteriores viram `superseded`; o clique também gera `chat_messages(role='customer', text=label, button_id)`.

## Reconhecimento (§3)
Assim que a sessão é criada, ANTES de qualquer turno n8n, monta+persiste o prompt `debt_acknowledgement` com resumo objetivo (credor, valor atualizado, N faturas, vencimento mais antigo) e a pergunta Sim/Não. Determinístico (funciona com n8n|stub|disabled). Toda resposta grava numa transação: `debt_acknowledgements` (append-only: session_id, customer_id, debt_id=primary, acknowledged, button_id(0|1), prompt_id, source='chat_button', ip_hash, user_agent) + `chat_prompts.answered` + `chat_messages` (label) + `journey_events` (`debt.acknowledged`|`debt.not_recognized`). View `debt_acknowledgement_latest` = última resposta por (session_id, debt_id).
- **Sim(1)**: prossegue; 1º chat.turn leva `debt_acknowledgement.acknowledged=true`.
- **Não(0)**: registra e entrega ao n8n (default `continue` — não bloqueia navegação). Configurável `on_debt_not_recognized`: continue|dispute|human. **Invariante:** com acknowledged=false, `payment.create` recusa **409 `debt_not_acknowledged`** (salvo `allow_payment_without_acknowledgement=true`, default false) → registra `offer.rejected(reason='debt_not_acknowledged')`.
- Textos aprovados: prompt "**{credor}** · valor atualizado **R$ X**, **N** fatura(s), vencimento mais antigo em **dd/mm/aaaa**. Antes de começarmos: **você reconhece esta cobrança em seu nome?**" `[1] Sim, reconheço` `[0] Não reconheço` (`[99]` opcional via `show_handoff_button`). "Não" (assistido): "Tudo bem. Posso te mostrar o detalhe das faturas para você conferir. Se ainda assim não reconhecer, você pode registrar uma contestação ou falar com nosso atendimento — e nada é cobrado enquanto isso."

## Pagamento (§4) — sequência
payment.create: valida sessão+offer (presented, não expirada, da sessão) → verifica reconhecimento → **revalida termos contra a matriz VIGENTE** (divergência → 422 com código) → guard idempotência (409 already_charged) → cria agreement+cobrança pelo caminho existente (`externalReference=journey_{sessionId}_{offerId}` sem `:`, `origin='chat_journey'`) → grava acceptances/eventos, demais ofertas superseded → **responde o link** (Apêndice B.1). **Idempotente por `(session_id, offer_id)`**: 2ª chamada devolve payload IDÊNTICO (mesmo agreement/link) com `idempotent:true`, zero cobrança nova. Worker off → `{status:'processing',poll_after_ms:3000,agreement_id}` sem link; n8n consulta `payment.status` até obter URLs.
Ações novas papel B: `chat.send` (empurra mensagem+opcional prompt+payment_ref; grava chat_messages(assistant)+n8n_execution_id; dedupe por event_id 24h), `prompt.ask` (só prompt), `prompt.close`. UI recebe via `GET /api/chat/messages?since=` (polling 2–3s, para em visibilitychange, teto 20min). Card do acordo continua sendo da plataforma (colunas reais de agreements), independente da mensagem do n8n.
