# Runbook — Ativação do envio de negociação via Voxuy (sair do `mock`)

**Data:** 2026-09-22
**Escopo:** ligar o disparo REAL por WhatsApp (Voxuy, dialeto `enterprise_v1`) no
"Enviar Negociação" de `/super-admin/negociacoes`. Até aqui o default é `mock`
(nada sai do processo). A **credencial (URL da Voxuy) chega depois** — este
runbook deixa tudo pronto e documenta a ordem exata para a virada.

> **REGRA DE SEGREDO:** a `VOXUY_WEBHOOK_URL` **é a credencial** (contém o
> `companyId` embutido). Ela mora **só em variável de ambiente**. **NUNCA**
> commitar, colar em Slack/ticket, nem logar. O código já garante: a URL nunca
> aparece em log (só `id`/`dialect`/`http`). Placeholders neste doc:
> `<VOXUY_WEBHOOK_URL>` e `<voxuy_flow_id>` — nunca valores reais.

---

## 0) Pré-requisitos (uma vez, antes da virada)

- [ ] A jornada está no ar com as flags do chat (não é objeto deste runbook).
- [ ] Worker Fargate `alteapay-workers` **rebuildado** com o código atual do
      `feature/journey-neutral-prelogin` (o processamento por fila roda no
      worker; imagem antiga não tem o `VoxuyApiProvider` `enterprise_v1`).
      Se o disparo for `inline` (`DISPATCH_MODE=inline`), roda na request do
      Next e o worker não é o caminho — mas confira mesmo assim.
- [ ] Telefones dos devedores em **E.164** (`+55DD9XXXXXXXX`). O provider
      **barra** qualquer telefone fora de E.164 antes de sair (nada é enviado);
      esses contatos caem como `sem_celular_valido`/falha de validação.

---

## 1) Config por TENANT (Supabase → `tenant_chat_config`, linha do `company_id`)

Ordem recomendada: **primeiro** garanta link/flow/telefones, **por último** vire
o provider (assim, no instante em que virar, já está tudo válido).

1. **Link único do cedente** — o WhatsApp carrega o link `/n/{code}`:
   - [ ] `public_link_code` preenchido (código opaco do cedente).
   - [ ] `public_link_enabled = true`.
   - Sem isso, WhatsApp ainda dispara (o link vai na variável), mas o e-mail
     de convite falha com `sem_link_publico` — então **habilite**.

2. **Flow da Voxuy por tenant:**
   - [ ] `voxuy_flow_id = <voxuy_flow_id>` (INTEIRO; o id do fluxo no painel
     Voxuy). Ele sobrescreve o env `VOXUY_FLOW_ID`; o env é só fallback.

3. **Vira o provider para Voxuy (o switch do disparo):**
   - [ ] `whatsapp_provider = 'voxuy'`  ← **este é o switch efetivo** do
     caminho de envio do hub. A campanha faz *snapshot* de `whatsapp_provider`
     em `whatsapp_campaigns.provider`; o worker lê isso e escolhe o provider.
   - [ ] `whatsapp_dispatch_mode = 'voxuy_api'`  ← **setar junto**, por
     consistência. Ele alimenta `loadTenantHubConfig` e mantém o painel
     coerente. (Detalhe técnico: o roteamento do envio hoje decide por
     `whatsapp_provider`; o `whatsapp_dispatch_mode` isolado **não** vira o
     disparo. Por isso setamos **os dois**.)

> **Status honesto (V7):** com `whatsapp_provider='voxuy'`, a resposta 200 da
> Voxuy é registrada como **`accepted`** (aceito p/ agendamento), **não**
> `delivered`. Entrega/leitura só aparecem se houver fonte real
> (`provider_status_source != 'none'`, via webhook inbound). Isso é intencional.

---

## 2) Variáveis de AMBIENTE (Netlify + Fargate) — a credencial

Setar **nos dois ambientes** que rodam envio: **Netlify** (disparo `inline` na
request) e **Fargate** (disparo por `queue`, no worker). Se não sabe qual está
ativo, configure ambos.

| Variável | Valor | Obrigatória | Observação |
|---|---|---|---|
| `VOXUY_WEBHOOK_URL` | `<VOXUY_WEBHOOK_URL>` | **sim** | **É A CREDENCIAL.** https:// . Só env. Nunca logar/commitar. |
| `VOXUY_DIALECT` | `enterprise_v1` | não | É o **default**; pode omitir. Não use `transaction_v1`/`custom` sem motivo. |
| `VOXUY_FLOW_ID` | `<voxuy_flow_id>` | não | Fallback global; o **tenant** (`voxuy_flow_id`) tem precedência. |
| `VOXUY_TIMEOUT_MS` | `10000` | não | Default 10s; 1 tentativa por job. |

Não precisa de `VOXUY_API_TOKEN`/Bearer no `enterprise_v1` — a conta é
identificada **pela URL**. (`VOXUY_API_TOKEN` só existe para o legado
`transaction_v1`.)

> Se a URL estiver ausente/incompleta quando o provider for `voxuy`, o
> `VoxuyApiProvider` **recusa na construção** (erro de **config**): a mensagem
> falha e a **campanha é pausada** (não fica batendo com credencial errada). O
> erro aparece no painel; **nada sai**. Isso é o comportamento fail-safe.

---

## 3) Smoke test (1 contato de teste — obrigatório antes do lote)

1. [ ] Escolha **1 devedor de teste** com **seu próprio** número em E.164
       (ou de alguém do time que confirme o recebimento).
2. [ ] Em `/super-admin/negociacoes`, filtre por **este cedente** e selecione
       **só esse 1 devedor**.
3. [ ] (Opcional) **"Simular (dry run)"** primeiro: confirma elegibilidade,
       canal e link **sem enviar**. O resumo deve mostrar **Simuladas = 1**.
4. [ ] **"Confirmar e enviar"** (sem dry run). Acompanhe:
   - Barra de progresso + contagem durante o envio.
   - Resumo final: **Enviadas = 1** (ou **Falharam = 1** com motivo legível).
   - A coluna **Estágio** da tabela deve sair de "Na fila" → "Enviado"
     (`accepted`); e evoluir com o webhook inbound, se houver.
5. [ ] Confirme o **recebimento no WhatsApp** do número de teste e que o **link
       `/n/{code}` abre** a jornada.
6. [ ] Cheque os logs (Netlify e/ou `aws logs tail /ecs/alteapay-workers`):
       deve haver `"[voxuy-api] send id=… dialect=enterprise_v1 http=200
       accepted=true"`. **A URL não aparece** — correto. Se aparecer PII/URL,
       **PARE** e reverta (isso seria bug).

Só prossiga para o lote real com o smoke **verde** (recebido + link abre).

---

## 4) Lote real

- [ ] Selecione os devedores do cedente (ou "todos os N filtrados").
- [ ] Prefira lotes controlados; o rate-limit da fila é conservador
      (`WHATSAPP_RATE_LIMIT_PER_SEC`, default 5/s).
- [ ] Acompanhe o resumo (enviadas/simuladas/falharam/suprimidas/ignoradas) e a
      lista de falhas. Falhas de **config** pausam a campanha (esperado).

---

## 5) Rollback (voltar para `mock` — nada mais sai)

Instantâneo e por-tenant. Na linha do `company_id` em `tenant_chat_config`:

- [ ] `whatsapp_provider = 'mock'`   ← reverte o switch (**suficiente** para
      parar o envio real; novas campanhas voltam ao mock).
- [ ] `whatsapp_dispatch_mode = 'mock'`  ← setar junto, por consistência.

Efeito: as **próximas** campanhas/mensagens não saem do processo (o mock só
grava eventos simulados). Mensagens **já `queued`** com `provider='voxuy'` no
snapshot continuam Voxuy ao serem processadas — se precisar cortar isso também,
**pause a campanha** (`whatsapp_campaigns.status = 'paused'`) para o worker
pular os jobs pendentes.

Rollback "duro" (corta a credencial de vez): **remover `VOXUY_WEBHOOK_URL`** do
env. Aí qualquer tenant em `voxuy` passa a falhar como **config** (campanha
pausa, nada sai). Use se suspeitar de vazamento/credencial errada.

## Checklist rápido da virada

```
[ ] worker rebuildado (se queue) / env no Netlify (se inline)
[ ] tenant: public_link_code + public_link_enabled=true
[ ] tenant: voxuy_flow_id = <voxuy_flow_id>
[ ] env: VOXUY_WEBHOOK_URL = <VOXUY_WEBHOOK_URL>   (segredo; só env)
[ ] tenant: whatsapp_provider='voxuy' + whatsapp_dispatch_mode='voxuy_api'
[ ] smoke 1 contato → recebido + link abre + log http=200 accepted=true
[ ] lote real
Rollback: whatsapp_provider='mock' (+ dispatch_mode='mock'); duro: remover VOXUY_WEBHOOK_URL
```
