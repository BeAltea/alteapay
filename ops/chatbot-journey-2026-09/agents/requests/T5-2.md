## T5 pede: adicionar link "Negociações (status)" na sidebar do super-admin

- **Arquivo alvo:** `components/super-admin/super-admin-sidebar.tsx` (fora do ownership de T5;
  T5 só possui `components/super-admin/negotiations/**`).
- **Motivo:** T5 entregou a rota `/super-admin/negociacoes` (lista de status por devedor +
  seleção + envio + detalhe). A rota funciona por URL direta, mas não há entrada na
  navegação. Precisa de um item no grupo OPERAÇÕES para o operador chegar sem decorar a URL.
- **Mudança proposta:** no array `navigationSections`, grupo `OPERAÇÕES`, adicionar um item
  (reusando o ícone `Handshake` já importado):

  ```ts
  {
    name: "Negociações (status)",
    href: "/super-admin/negociacoes",
    icon: Handshake,
  },
  ```

  Sugestão de posição: logo abaixo de "Negociações Chat". `isItemActive` já casa por
  `startsWith(href)`, então o detalhe `/super-admin/negociacoes/[customerId]` também acende
  o item — sem outra mudança.
- **Bloqueia?** NÃO. A página é acessível por URL/`Link` (o botão "Detalhe" da lista e o
  "← Voltar" do detalhe já navegam corretamente). É só descoberta na navegação.

---

### Nota (não é request, é fronteira): API de envio é de T2

O diálogo de envio de T5 (`components/super-admin/negotiations/send-dialog.tsx`) chama
`POST /api/super-admin/negotiations/send-preview` e `/send`, que são **de T2**. T5
desenvolveu **contra o contrato** (tipos em `components/super-admin/negotiations/send-contract.ts`:
`SendRequestBody`, `SendPreviewResponse`, `SendResponse`, desfechos
`sent|failed|suppressed|skipped`, `mode` `whatsapp_chat|charge_email|both`, `dryRun`,
`allowedModes`, `publicLink` `/n/{code}`). Quando T2 publicar essas duas rotas, o diálogo
já as consome. Se o formato divergir, ajusto o `send-contract.ts` (meu arquivo) — sem tocar
em T2. Enquanto as rotas não existem, o diálogo mostra "Falha ao pré-visualizar (404)" de
forma graciosa, sem quebrar a lista.
