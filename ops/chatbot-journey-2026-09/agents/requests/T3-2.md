## T3 pede: passar `voxuy_flow_id` do tenant ao provider no envio da campanha

- **Arquivo alvo:** `lib/journey/campaign-send.ts` (dono: **T2**)
- **Motivo:** o dialeto DEFAULT da Voxuy agora é `enterprise_v1` (contrato REAL
  verificado). O corpo exige `flowId` (inteiro), que deve vir de
  `tenant_chat_config.voxuy_flow_id` (integer, já adicionado por T1) e só cai no
  env `VOXUY_FLOW_ID` como fallback. Hoje `processCampaignMessage` chama
  `getWhatsAppProvider(msg.provider)` passando **só a string** do provider — o
  `voxuy_flow_id` do tenant NÃO chega ao `VoxuyApiProvider`. Sem essa mudança, o
  flowId por-tenant é ignorado e só o env é usado.

- **Mudança proposta (mínima, aditiva):**
  1. Incluir `voxuy_flow_id` no `select` do `tenant_chat_config`:
     ```ts
     .select("link_ttl_hours, whatsapp_sender_label, branding, voxuy_plan_id, voxuy_events, voxuy_flow_id")
     ```
  2. Montar um `apiConfig` e passá-lo à fábrica em vez da string, quando o modo
     for `voxuy_api`. Ex.:
     ```ts
     import { loadVoxuyApiConfig, coerceFlowId } from "@/lib/whatsapp/voxuy/config"
     // ...
     const base = loadVoxuyApiConfig() // já valida credencial/dialeto/URL (env)
     const apiConfig = {
       ...base,
       flowId: coerceFlowId(cfg?.voxuy_flow_id) ?? base.flowId,
       planId: cfg?.voxuy_plan_id ?? base.planId,
     }
     const provider = getWhatsAppProvider({ dispatchMode: msg.provider, apiConfig })
     ```
     `coerceFlowId` e `loadVoxuyApiConfig` já são exportados de
     `lib/whatsapp/voxuy/config.ts` (ownership T3). A fábrica
     `getWhatsAppProvider` já aceita `{ dispatchMode, apiConfig }`.
  - Alternativa (se T2 preferir não carregar env aqui): manter a chamada por
    string e apenas garantir que `VOXUY_FLOW_ID` esteja no ambiente — nesse caso
    o `voxuy_flow_id` por-tenant fica inativo (aceitável se todos os tenants
    usarem o mesmo flow).

- **Bloqueia?** NÃO para o mock (default de produção = mock, nada sai). Bloqueia
  apenas o uso de **flowId por-tenant** quando `enterprise_v1` for ligado em
  produção com fluxos diferentes por tenant. Com um flowId único por conta, o env
  `VOXUY_FLOW_ID` já cobre.
