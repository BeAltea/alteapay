## T2 pede: coluna `channel` em `whatsapp_messages` (migration)

- **Arquivo alvo:** `supabase/migrations/20260922_hub_link_status.sql` (dono: **T1**)
  — ou uma migration aditiva nova, à escolha do orquestrador.
- **Motivo:** o Hub/link único grava **1 registro por devedor** em
  `whatsapp_messages` com o canal usado (`whatsapp` | `email`) — exigido pelo
  contrato (§ Hub, item 2). Hoje a tabela (criada em `20260916_chat_journey_core.sql`)
  NÃO tem coluna `channel`; ela existe em `contact_suppressions` e em
  `negotiation_sessions`, mas não em `whatsapp_messages`. Sem a coluna, o
  `insert` do `runHubSend` (lib/journey/campaign-send.ts) falha em produção.
- **Mudança proposta (mínima, aditiva/idempotente):**
  ```sql
  alter table public.whatsapp_messages
    add column if not exists channel text
    check (channel is null or channel in ('whatsapp','email'));
  create index if not exists idx_wa_messages_company_channel
    on public.whatsapp_messages (company_id, channel);
  ```
  (`channel is null` aceito para não invalidar linhas legadas do worker antigo,
  que não setam canal — elas são todas WhatsApp por natureza.)
- **Bloqueia?** SIM para o disparo por e-mail do hub em produção (o insert
  quebra). NÃO para os testes (fake supabase aceita a coluna) nem para o modo
  WhatsApp puro se a coluna for opcional. Enquanto a migration não é aplicada, o
  hub roda contra o banco seeded local; a coluna precisa existir antes do GATE.
- **Alternativa (se preferirem NÃO tocar a migration agora):** eu passo a gravar
  `channel` dentro de `provider_payload` (jsonb já existente). Menos consultável,
  mas não exige DDL. Aviso se o orquestrador escolher esse caminho para eu ajustar
  o `insert`.
